# Third-party runtime inventory

This document inventories third-party software and services used by the
current NovaPeptide workflow. It is an audit aid, not a lockfile and not a
grant of rights. Production identity remains owned by the cited repository
constants, versioned protocols, environment selectors, and runtime validators.
If this document and production code differ, treat the deployment as not
audited and update both in the same review.

The inventory was checked against the repository and official upstream
sources on 2026-08-14. `Machine-enforced` means the current production path
rejects a different identity. `Availability/observed` means the path or tool
must exist and a revision may be reported for diagnosis, but production does
not reject a different revision. A successful server observation is useful
deployment evidence only; it does not create a new production pin.

## Authority map and maintenance rule

- ColabDesign commit: `agents/design/config.py` and
  `prediction_pipeline/contracts.py`; enforced by Design and Prediction
  ColabDesign runtime validation.
- LigandMPNN model type/checkpoint filename: `protocols/design_v1.json`,
  resolved by `agents/design/config.py`; only path/file availability is
  currently validated.
- Boltz version/model/checkpoint digest: `prediction_pipeline/boltz_worker.py`.
- PyRosetta version: `prediction_pipeline/rosetta_worker.py`.
- PRODIGY distribution version: `prediction_pipeline/execution_identity.py`,
  enforced by `prediction_pipeline.adapters.validate_prodigy_runtime`.
- Runtime paths and environment selectors: `agents/design/config.py` and
  `execution/config.py`.

Any change to one of those authorities requires a same-review update to this
inventory and the documentation consistency regressions. Never add a commit or
checksum gate solely because a value was observed on one server. Conversely,
do not weaken or relabel an existing machine-enforced identity as merely
observed.
