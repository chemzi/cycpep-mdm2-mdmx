# 赵嘉策上手说明

嘉策，这份是给你有空看项目时用的，不是一个需要一次性做完的任务单。

我们现在 Week 1 比较重要的一件事，是向 mentor 证明“流程能跑起来”：不一定要马上跑出完美候选，但至少要让 Research、Design、Prediction、Critic/Planner 这些模块之间有清楚的数据流、状态流和失败记录。你这边如果能帮我们把流程调度、规则检查、dry-run 这些工程部分先搭一点起来，就已经很有帮助。

你不需要先补很多生物背景。这个项目里的生物部分可以先粗略理解成：

- 我们在做 MDM2 / MDMX 相关的环肽设计。
- 目标是生成 8-20 个氨基酸长度的头尾环肽候选。
- p53 上的 F19 / W23 / L26 是三个很重要的结合锚点，后面会检查候选有没有打到这些位置。
- 七层指标电池就是一组筛选关卡：结构质量、界面置信度、结合物理、环化几何、热点覆盖、多模型一致性、自洽折叠。

你先不用判断某个残基合不合理，也不用实现 ColabFold、Rosetta、HADDOCK 这类重工具。比较适合你先看的，是项目怎么组织成一个能调度、能恢复、能审计的 agent workflow。

## 有空可以先做的小块

下面每一块都可以独立做，不用全接。

### 1. 给 Planner 写一个最小 `plan()`

文件：`agents/planner.py`

第一版可以很简单：

- 如果还没有 research 结果，就返回一个 research task
- 如果 research 有了但候选池为空，就返回 design task
- 如果有候选但没评分，就返回 prediction task
- 如果已经有评分，就返回 critic task

输出用 list of dict 就行，例如：

```python
[
    {
        "agent": "research",
        "action": "run",
        "phase": "research",
        "reason": "no research result in state",
    }
]
```

### 2. 给 Critic 写几个不依赖 bio 的检查

文件：`agents/critic.py`

可以先检查这些很工程化的问题：

- 候选池是不是空的
- 序列有没有大量重复
- 候选有没有缺 `manifest_path`
- 有没有候选还没有评分
- 阈值是不是还没标定

输出也用 dict，比如：

```python
{
    "status": "needs_attention",
    "issues": [
        {
            "code": "empty_candidate_pool",
            "message": "No candidates found in CandidateIndex.",
        }
    ],
}
```

### 3. 做一个 dry-run 脚本

可以新建：`scripts/run_pipeline.py`

先不用真的跑重模型。第一版只要能：

- 调 `planner.plan()`
- 打印下一步要做什么
- 加一个 `--dry-run`
- 出错时给出清楚信息

这样我们就能很快给 mentor 展示：流程不是散的，已经能被一个调度入口串起来。

### 4. 补一点测试

可以新建：`test_planner_critic.py`

优先测最简单的东西：

- 空 state 会安排 research
- 有 research 但没有 candidate 会安排 design
- 空 candidate pool 会被 critic 报出来
- 重复 sequence 会被 critic 报出来

这些测试不需要 GPU，也不需要生物工具。

## 一个比较舒服的第一步

如果你不想一下看太多，可以先只做这个：

1. 打开 `agents/planner.py`
2. 写一个 `plan(state=None)` 函数
3. 让它能根据 state 返回下一步 task
4. 加一个最小测试

做到这里就已经能帮我们把 Week 1 的“流程能跑通”往前推一截了。

## 不确定 bio 细节时

直接留清楚的 code / message 就行，不用卡住。

例如：

```python
{
    "code": "threshold_needs_review",
    "message": "L3 threshold exists but calibration_status is pending.",
    "owner_hint": "prediction/research",
}
```

这样我们后面懂对应部分的人可以接着补，你这边的 workflow 不会被细节挡住。
